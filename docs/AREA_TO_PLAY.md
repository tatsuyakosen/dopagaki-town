# 第一段階：日本地図で選んだ場所を遊べる街にする

日本地図でエリアを選び、利用可能な実都市データを使って操作可能な3Dステージを構築する。
梅田は最初の検証地点で、地域専用の形状コードを前提にしない。
建物・道路の配置は実データから取得し、データのない部分を「実際の街」として創作しない。

## 現在の実装

`/map.html` で中心と1km外枠を選択 → 中央250mの建物・道路／利用条件を確認 → 構築ジョブ → `/walk.html?stage=...` へ進む。
同条件の完成データを再利用し、未完成や失敗したデータを歩行画面へ渡さない。
詳細な起動・取得・制限は [CITY_WALK.md](CITY_WALK.md)、実測と検証限界は [CITY_WALK_TESTS.md](CITY_WALK_TESTS.md) を参照。

| 項目 | 状態 |
| --- | --- |
| 日本地図・座標入力・1km／250m表示 | 実装。地理院タイル＋Leaflet |
| bboxカタログ検索 | 実装。建物・道路が必要。複数自治体の結果は未対応 |
| 年度・利用条件・来歴 | 実装。対応するmetadata XMLのCC BY 4.0だけを自動採用。他条件は要確認 |
| 自動取得・変換・中止・容量制限 | 実装。TypeScriptを別Node.jsプロセスで実行 |
| キャッシュと圧縮配信 | 実装。確認15分、元データ／完成ファイル24時間 |
| AI計画 | 任意のGemini ADKアダプターを実装。現在の役割はLOD上限選択のみ。実APIは未検証 |
| AIなしの自動構築 | 実装。「AI未接続」と明示 |
| 街歩き | 移動・ダッシュ・追従カメラ・独立Collider・夕景を接続 |
| 実データ確認 | 梅田の離れた2街区で変換・NullEngine衝突検証を実施 |
| 全国の全地点 | 未達成。データ形式・利用条件・容量で構築できない地域あり |
| 実ブラウザの3D／FPS | 未検証。今回のブラウザ環境はWebGLを利用不可 |
| 1km全域・実都市PvP | 未実装 |

この段階で製品全体の完成とは扱わない。地図の表示と選択はできても、すべての地点に対応データがあるわけではない。

## AIと実データの責務

形状、座標変換、三角形化、取得先検証、開始地点・容量検査は決定的なコードで行う。
AIは検証可能な構築計画を提案する。現在の計画はLOD1/2の上限に限定し、低品質ではLOD1以外を拒否する。
データ候補・素材・街区展開の包括的なAI計画、AIがツールを順次呼び分ける仕組みは今後の拡張である。
既存Directorの試合中介入とは別の責務にする。
AI未接続の固定ルールを「AIが構築した」と表示しない。

建物・道路の形状は整備年度の記録を基準とする。窓・材質・夕景は演出と表示し、写真テクスチャの再現と区別する。
測量年度が不明ならnullを保持し、整備年度や取得日で代用しない。
通信失敗、データ不足、条件要確認、容量超過、変換失敗を区別して案内する。

## 構築API

ローカルのVite middlewareで提供する。公開用の認証・利用者別の課金管理は未実装。

| API | 用途 |
| --- | --- |
| GET /api/city/status | AI接続設定・構築中状態 |
| POST /api/city/catalog | 緯度経度から確認ID、年度、条件、元容量を取得 |
| POST /api/city/jobs | 確認ID＋low/balancedで開始 |
| GET /api/city/jobs/:id | running / ready / failed / cancelled と実際の処理段階 |
| DELETE /api/city/jobs/:id | 中止 |
| GET /api/city/stages/:id | 内容ハッシュで識別する検証済みJSON。gzip配信 |

処理段階は plan → download → convert → validate → ready。
進捗率を推測して埋めず、処理段階と取得済みファイル数を表示する。
書込APIは同一オリジンの専用ヘッダーを要求し、任意URL・コマンド・追加フィールドを拒否する。
鍵・大きな都市データ・キャッシュ・選択履歴・生ログは公開Gitに入れない。

## 完了に向けて残る受入条件

- WebGL対応の実機で、地図選択から入場、歩行、ダッシュ、壁沿い、カメラ、落下復帰を通して確認する。
- 標準30FPS以上／軽量20FPS以上を目標に、実機GPU、メモリ、長時間歩行、初回ロードを計測する。
- 実AIの計画・失敗・取消を確認し、役割を候補データの選定まで広げる。
- 梅田以外の自治体で、年度・ライセンス・LOD・歩行を確認する。重複カタログと複数自治体の安全な選定に対応する。
- 原データにない通行面を創作せず、歩道・地形・写真テクスチャを扱う範囲を増やす。
- 最初の街区を検証後に1km全体のタイル配信とLOD切替を実装する。
- 実都市PvPでは、同じ形状ハッシュに対応するサーバー判定、経路グラフ、動的ゲート検証を接続する。
