# 第一段階：日本地図で選んだ場所を、遊べる街にする

## 製品の中心となる体験

日本地図でエリアを選択すると、AIが利用可能な実都市データを調べ、
その場所を操作可能な3Dステージに組み立て、利用者が街へ入れる。
最初の目的はこの一連の体験を成立させること。梅田は最初の検証地点であり、製品の固定地域ではない。

利用者の基本操作は「場所を選ぶ」「街を構築する」「街で遊ぶ」の3つ。
都市データの手動ダウンロードや変換コマンドの実行を通常の利用手順にしない。
既存の街歩きと変換器は下位の基盤であり、この体験を実装済みとは扱わない。

## 最初の利用フロー

1. 日本地図を移動・拡大し、中心点と1km×1kmの範囲を選ぶ。梅田等の候補地点はショートカットとして扱う。
2. 選択範囲のデータ年度・建物／道路／地形・外観テクスチャの有無・利用条件を確認する。
3. 「街を構築する」でジョブを開始する。データ確認、取得、変換、歩行検証の実際の進捗を表示する。
4. 完成した街区から入り、移動・ダッシュ・カメラ・衝突を使って遊ぶ。
5. 地図へ戻って別地域を選ぶ。同条件の完成済みステージは再利用する。

最初は1kmの選択範囲内の250m街区を完成させ、検証済み範囲を地図とゲーム画面で示す。
全域を読み込み終わったように見せない。全国の場所を選べるUIと、全地点を再現できるデータの存在は別に判定する。

## AIと実データの役割

| 処理 | 方針 |
| --- | --- |
| 建物・道路・地形の位置と形状 | 記録された実データを基準にし、LLMに座標や建物を創作させない |
| データ選定 | AIがカタログの候補から年度・LOD・素材・容量を比較し、検証可能な構築計画を返す |
| 取得・変換 | 許可された取得／変換ツールをAIが順に実行。座標変換・切出し・メッシュ生成は決定的なコードで行う |
| 遊べる状態への調整 | 実測の通行面から計算した候補を使い、開始地点・カメラ・描画品質を選定。衝突・経路検査を通す |
| 演出 | 夕景・窓の光・汎用素材は演出として区別。実測外観テクスチャがある場合はその出典を維持 |
| 不足・失敗 | 理由と代替可能な地域を示す。データなしやAI未接続を成功扱いにしない |

AIは実都市を遊べる形へ自動構成する担当とする。実データを読み込むだけの処理や
固定ルールへの縮退を「AIが構築した」と表示しない。既存Directorの試合中の都市介入とは責務を分ける。
AIが出した計画も、データ年度・利用可能なファイル・容量制限・歩行検査で検証してから採用する。

## データ取得の実装候補

2026-09-07に確認した公式仕様:

- [PLATEAU CityGML API](https://docs.plateauview.mlit.go.jp/datasets/citygml/)には、矩形の緯度経度範囲からファイルを探す検索がある。
  座標条件は `r:西端の経度,南端の緯度,東端の経度,北端の緯度`、地物型は `bldg,tran,dem` を対象とする。
- [データカタログAPI](https://docs.plateauview.mlit.go.jp/api/rest/operations/datacatalogplateau-datasets/)の整備年度・LOD・テクスチャ有無等を候補比較に使う。
- [3D Tiles / MVT配信](https://docs.plateauview.mlit.go.jp/datasets/3d-tiles/)は描画用モデル取得の候補。
  配信は試験運用であるため、障害時は取得失敗として扱い、検証済みキャッシュの再利用を設計する。

カタログの市名だけで選択範囲全体の詳細データがあると判定しない。
地物別の実際の範囲・欠落・LOD・利用条件を確認する。地図背景だけでは3D再現を成立させない。
`latest` は検索時に利用しても、構築結果には採用した具体的年度・リソース・ハッシュを固定する。
測量年度が不明なら不明と表示し、整備年度や取得日で代用しない。

## 構築ジョブと実行境界

これは実装予定の契約であり、既存APIとして公開済みではない。

- 入力: 中心座標、範囲、初期街区、品質プリセット。任意URL・コマンド・秘密情報は入力として受け取らない。
- 状態: `checking` → `fetching` → `converting` → `validating` → `ready`。
  必要に応じて `unsupported`（不足確認済み）、`failed`（取得／変換失敗）、`cancelled` に遷移する。
- 出力: ステージID、検証済み範囲、来歴、演出の範囲、描画モデルと独立Collider、開始地点。
- キャッシュ: 範囲＋採用データ版／ハッシュ＋変換器版＋品質条件をキーにする。更新時に古い形状と判定を混在させない。
- 制限: 同時ジョブ数、取得容量、処理時間、AI呼出回数をサーバー側で制限し、取消と部分失敗に対応する。
- 公開範囲: APIキーはサーバーのみ。大容量データ・キャッシュ・選択履歴・生ログはGitに入れない。
  公開配信するモデルには配布可能な情報だけを含める。

対応可否は「詳細再現可能」「形状のみ」「データ不足」「確認失敗」を区別する。
通信失敗をデータ不足と断定しない。写真素材のない地域では、実物と同じ外装を約束しない。

## 第一段階の受入条件

- 日本地図から異なる2地域を選び、地域専用コードや手作業の変換なしで、それぞれ街区を構築できる。
- 実AIによる計画とツール実行を確認でき、AI停止時にも状態を偽らず再試行できる。
- 選択範囲と街の原点・建物配置・道路が一致し、採用年度と利用条件を確認できる。
- 成功した街区で実際に歩行・ダッシュでき、地面・建物との衝突とカメラが機能する。
- データ不足、通信失敗、変換失敗、取消、同じ地域の再構築を実ブラウザで確認する。
- 初回構築時間、再利用時の待ち時間、転送量、実行時メモリ、FPSを計測して結果を残す。
- 上記が通るまでは、固定ステージの成功や単体テストだけで「選んだ街で遊べる」を達成したとしない。

## 現在の実装との差分

| 項目 | 現状 |
| --- | --- |
| 日本地図・範囲選択 | 未実装 |
| 範囲に応じたカタログ検索・対応範囲判定 | 未実装。公式取得経路を確認した段階 |
| AI構築計画・自動取得・変換ジョブ・キャッシュ | 未実装 |
| 複数地域への対応 | loaderが梅田の固定パス、変換器が梅田範囲限定。一般化が必要 |
| 単独街歩き | 移動・カメラ・独立Collider・夕景の基盤あり。実都市／実ブラウザは未検証 |
| 鬼ごっこへの接続 | 既存架空都市PvPあり。実データの判定・経路との統合は未実装 |

実装順は、地域選択と取得可否確認、1街区の自動構築、AI計画と再試行、別地域での再現性検証、
1km全域への拡張、実都市PvPへの接続とする。第一段階の完了には地域選択から遊ぶまでの接続を含める。
