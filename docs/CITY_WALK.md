# 地図で選んだ実都市の街区を歩く

第一段階の製品仕様は [AREA_TO_PLAY.md](AREA_TO_PLAY.md)、実測値と残る検証は [CITY_WALK_TESTS.md](CITY_WALK_TESTS.md) に記録します。
入口は `/map.html`。日本地図で1km四方の中心を選び、「この場所で歩く」で確認・構築・入場まで進みます。
中央250mから開始し、周辺を250m単位で先読みします。全25区画（外縁は125m幅）のうち、取得・検証できた街区間を移動できます。
梅田の25区画を取得確認し、15区画で構築成功、東側10区画は容量超過でした。全域で歩ける状態ではありません。地下・内部・実都市PvPは未実装です。

## 起動

Node.js 22.19以上（22系）または24.13以上、npm、WebGL対応のPCブラウザが必要です。
AIを使う場合はNode.js 24.13以上が必要です。

```sh
npm ci --ignore-scripts
npm run dev:client
```

表示されたURLの `/map.html` を開きます。梅田を選択 → 「この場所で歩く」。準備完了後に自動入場します。
WebGLに対応していないブラウザには構築開始前に案内します。ミニマップの青い街区を歩けます。
ミニマップの橙色は読み込み中です。「データの対応状況を確認」では構築前の確認だけを実行できます。
失敗時には近くの準備済み中央街区がある場合に最大3件の候補を表示します。
未取得の境界では止まり、取得失敗は「周辺を再試行」でやり直せます。地図の各地点ボタンは構築成功を保証するものではありません。
都市データの手動取得・変換は通常の操作に不要です。初回は配布元への通信に数十秒かかる場合があり、実際の処理段階を表示します。

Windowsでも同じnpmコマンドで起動します。Python・venv・pipの準備は不要です。
取得・XML解析・座標変換・三角形化をTypeScriptへ統一し、別Node.jsプロセスで実行します。
変換テストだけを実行する場合は `npm run test:city-converter`。通常の `npm test` にも含まれます。

既存の架空都市PvPも動かす場合は `npm run dev`。ブラウザは `/` が既存PvP、`/walk.html?fixture=1` が明示的な架空の操作検証です。
引数をViteへ渡す開発用ラッパーを追加し、既存Match Serverも維持しています。

```sh
npm run build
npm run check:city-bundle
npm run preview:client
```

previewも同一オリジンの構築APIを提供します。静的ファイルを置くだけでは構築APIは動きません。
Viteの開発・previewサーバーはローカル検証用です。認証付きの公開構築サーバー、Cloud Runへの接続、デプロイは今回未実装です。

## AIの設定と責務

設定なしでも固定ルールによる自動構築が動作し、画面に「AIプランナーは未接続」と表示します。
実AIの動作を偽装しません。任意でサーバープロセスに以下を設定します。

- `CITY_PLANNER=gemini-adk`
- `GEMINI_API_KEY` または `GOOGLE_API_KEY`。値はサーバーの環境変数管理で渡し、Git・チャット・フロントエンドへ入れません。
- `CITY_PLANNER_MODEL` は任意。既定値は `gemini-2.5-flash`。

`VITE_` 接頭辞の鍵はブラウザへ公開されるため使用しません。この起動コマンドは秘密情報のある.envを自動読込しません。
AIへ送るのは公開の市名・年度・ファイル数・容量・品質条件だけです。鍵は変換ワーカーにも渡しません。
現時点のAIの役割はLOD上限1/2の計画選択に限定し、取得先・形状・実行コードは生成させません。
低品質でLOD2、追加フィールド、上限外の計画は拒否します。AI失敗時は構築失敗として案内し、AI成功と表示しません。
実API呼出しは今回未検証です。

## 遅くしないための制限

| 対象 | 実装した制限 |
| --- | --- |
| 地図の初回JavaScript | 3Dエンジンを分離。gzip 80KiBを超えるとCIで失敗 |
| 最初に構築する範囲 | 中央250m × 250m。周辺を共通原点の別街区として取得 |
| 取得する地物 | PLATEAUの建物・道路、国土地理院の小さな標高タイル。市全体ZIP・巨大CityGML DEM・写真テクスチャは取得しない |
| 元データ | 1ファイル32MiB、合計64MiB、最大8ファイル |
| 標高タイル | DEM / zoom 14 / text形式のみ。1タイル768KiB以下、最大9枚・合計5MiB以下。地面は12.5m間隔で補間 |
| ブラウザ用街区 | JSON 4MiB、最大600メッシュ、LOD1は4万頂点、LOD2上限は8万頂点 |
| ブラウザの保持範囲 | 最大5街区、低品質は合計10万頂点／標準18万頂点。現在地を残して遠い街区から解放。共通地物は参照を共有 |
| 同時処理 | 確認1件、構築1件。建物・道路ファイルは最大2件ずつ取得。追加構築をキューに溜めずBUSYを返す |
| 制限時間 | 確認90秒、構築240秒、AI計画30秒。取消で子プロセスを停止 |
| キャッシュ | 確認15分、取得ファイル24時間／256MiB目安、完成ファイル24時間／64MiB上限。中央・周辺街区の入場索引は合計最大128件 |
| 描画・判定 | 約6msごとにメッシュ配置を中断してUIへ制御を返す。16m格子で近傍Colliderに絞る |
| 品質 | 低解像度・影なしを選択可能。24FPS未満が続くと軽量品質へ切替 |

同じ構築条件の完成ジョブは同一プロセス内で再利用します。中央・周辺街区とも、再起動後も有効な完成データを直接開き、カタログ確認と再変換を省略します。
原点・街区番号・品質・プランナーごとに分離し、期限切れ・削除済み・条件の異なる街区を返しません。
先読みは進行方向の最大175m先を優先します。通信・混雑の一時エラーは間隔を空けて最大3回自動再試行し、容量不足は無限に再試行しません。
完成ファイルのIDは内容のハッシュで、ブラウザにはgzipで転送します。期限切れ・削除済みの完成ファイルを成功キャッシュとして返しません。
キャッシュは古い年度を現況と偽るものではなく、年度・取得日・元ファイルのSHA-256を常に残します。
FPSの閾値は制御設定であり、実機で達成済みのFPSではありません。

## データ取得・変換

実装: `scripts/city-worker.ts`、`scripts/convert-citygml.ts`、`apps/city-builder/src/`。

XMLは [saxes](https://github.com/lddubeau/saxes) で街区の地物単位に読み、外部entity・DTDを拒否します。
三角形化には [Earcut](https://github.com/mapbox/earcut) を使い、元のXYZを保持して主平面へ投影し、穴を差し引いた面積を検査します。
metadata ZIPは [yauzl](https://github.com/thejoshwolfe/yauzl) で該当XMLだけを最大2MiBまで読み、ディスクへ展開しません。
これらはサーバー用の依存です。都市データの取得・変換コードを地図の初回バンドルには含めません。

1. [PLATEAU CityGML API](https://docs.plateauview.mlit.go.jp/datasets/citygml/)へ選択街区のbboxを問い合わせ、建物・道路ファイルを解決します。
2. 自治体ごとに最新整備年度を選び、最大4自治体を合成します。各入力ファイルの出典・年度とmetadataのハッシュを個別に保持します。重複URLの帰属が曖昧な場合は拒否します。
   容量情報のない旧カタログにはHEADで問い合わせ、確認できない場合はSOURCE_SIZE_UNKNOWNで停止します。サイズが不明なまま無制限に取得しません。
3. 配布元のmetadata ZIP内の該当する一般都市モデルXMLから利用条件を抽出します。
   現在は対応する `udx_<自治体コード>_city_<年度>_op.xml` にCC BY 4.0だけが記載され、追加制約がない場合を自動処理します。
   他の条件・命名方式は「要確認」とし、全PLATEAUが同じ条件とは仮定しません。
4. HTTPSの公式カタログ・配信ホストだけから取得します。リダイレクト先も検証し、任意URLをAPIで受け取りません。
5. 入力ごとのSHA-256を計算し、EPSG:6697から原点近傍のGRS80局所座標へ変換します。
6. 街区と交差する地物の形状を保持し、Earcutで穴を保った三角形へ変換します。頂点のXYZは補作しません。
7. 道路面上の開始候補を計算し、周囲60cmの地面と建物の屋根の重なりを検査します。ブラウザ側も上方rayで再検証します。
8. 年度・測量年度不明・利用条件・出典URL・ハッシュ・演出の範囲をCityManifestへ記録し、形状と容量を検証してから公開用データにします。

自動構築ではさらに [国土地理院の標高タイル](https://maps.gsi.go.jp/development/demtile.html) を取得します。
256×256の標高値を双線形補間し、街区ごとの12.5m格子にします。隣接街区は同じ原点・同じ座標で境界頂点を作り、継ぎ目を合わせます。
欠測値 `e` は0mに置き換えず、その街区の構築を止めます。出典・入力ハッシュ・利用条件を記録し、整備年度・測量年度は不明として保持します。
標高ゼロの平面道路は三角形を細分化してDEMに沿わせます。底面が標高ゼロの建物のみ、外形寸法を保ってDEMの代表標高へ平行移動します。
この高さ補正は推定を含むため実測値と区別して表示します。非ゼロ標高の道路・建物は元の高さを維持します。
DEMは縁石・階段・歩道や高架の詳細を表さず、水域・私有地の通行可能性も判断しません。

国土地理院の地図には [地理院タイルの出典](https://maps.gsi.go.jp/development/ichiran.html) を表示します。
地図の表示範囲は地図提供元へ、選択範囲は都市モデルの問い合わせ先へ送られます。現在地の自動取得はしません。

原データ、metadata ZIP、生成メッシュ、選択範囲のキャッシュはすべて `.local/city-build/` に保存し、Gitから除外します。
公開モデルにmetadataの連絡先・住所・生XMLはコピーしません。元モデルのテクスチャは含めません。

手動取得済みデータにも変換器を利用できます。同一データセットの年度・条件を確認したメタデータを指定します。
手動CLIは従来の単一街区変換で、地形取得・周辺ストリーミングは地図からの自動構築で利用します。

```sh
npm run convert:city -- \
  data/raw/building.gml data/raw/road.gml \
  --source-metadata .local/source-metadata.json \
  --origin 34.705,135.4967,0 \
  --block-half-size 125 --spawn 6.28,0.95,-11.02 \
  --out apps/game-client/public/city-data/umeda-block.json
```

ファイル名・開始地点は書式例です。元データと安全な開始点を確認してから指定します。
メタデータの必須フィールドは `title, provider, datasetYear, surveyYear, url, license, licenseUrl, attribution, retrievedAt`。
測量年度は不明ならnull。出典は資格情報・署名queryなしの公開HTTPS URLとし、未記入の値は拒否します。
手動出力の上限は従来の20MiB／50万頂点ですが、自動構築には上記の厳しい4MiB／4〜8万頂点を適用します。

## 操作と設計

| 操作 | 機能 |
| --- | --- |
| WASD | 視点方向の移動。斜め速度を正規化 |
| 左右Shift | ダッシュ。歩行3.2m/s、走行7m/s |
| ドラッグ／矢印キー | 追従カメラの向き |
| Esc／一時停止 | 入力を解除。タブ非表示・フォーカス喪失でも停止 |
| 開始地点へ | 最初の開始点へ復帰。その街区を解放済みなら初期ステージを再読込。落下時の自動復帰は直近の安全な足場 |
| ミニマップ・周辺を再試行 | 読み込み済み／未取得／失敗を表示。未取得の先には移動せず、準備完了後に境界を開く |
| 動作の重さを計測 | 歩行中60秒の実フレーム時間を記録。平均FPS・95パーセンタイル・長い停止・保持街区数などを端末へJSON保存 |
| 検証ゲート | 架空ステージ限定。ゲーム用Colliderを別管理 |

Visual World、Collision World、Game Overlayを別ノードで管理します。
Colliderは現在は元形状の独立コピーです。簡略化と精度検証は今後の工程です。
低FPS時の経過時間を40msで切り捨てる処理を修正しました。100msまでのフレームを最大1/60秒ずつの衝突更新に分割し、通常の15・20・30・60FPS間で移動速度を保ちます。
100msを超える停止は復帰時の大きな移動を防ぐため制限します。これは実機FPS達成の保証ではありません。
外壁材・窓の光・夕景は汎用の演出で、実際の外観・点灯・通行規制を示しません。

UTF-8 CityGML 2.0、明示的EPSG:6697、閉じた平面リングが対象です。LOD2がない建物はLOD1を使用します。
未展開XLink、5cmを超える非平面、巨大リング、未対応の形状・利用条件は拒否します。
自動構築の地面はDEMと道路です。歩道・階段・地下・内部・地形段差の完全再現はありません。
原点近傍の局所接平面と標高の近似を使い、ジオイド補正や測量精度を保証しません。

モバイル移動・ゲームパッド・NavMesh・距離別LOD切替・1km全区画の受入検証・実都市PvP接続は今後の対象です。
既存PvPは格子道路・矩形Colliderの架空都市であり、外観を重ねるだけで実都市の判定にはできません。

## ハッカソン前の街区準備

配布元への通信を来場者の待ち時間から外すため、同じチェックアウトで先に街区を構築できます。
開発・previewサーバーの構築と同時には実行せず、準備終了後にサーバーを起動してください。

```sh
# 中央と周囲の9街区（1km全体の確認は --radius=2、25街区）
npm run prepare:city-area -- --latitude=34.705 --longitude=135.4967 --radius=1
# 街区を指定して再開。xは東、zは南。範囲は -2〜2。
npm run prepare:city-area -- --latitude=34.705 --longitude=135.4967 --tiles=0:0,-1:0
npm run dev:client
```

1件ずつ構築し、完成済みなら再利用します。失敗した街区も結果を表示し、1件でも失敗すれば終了コード1です。Ctrl+Cで中止します。
データの期限は24時間です。選択原点・品質・プランナーが変わると別のキャッシュになります。
原本を小さく分割して配信する仕組みではなく、既存の取得上限内でブラウザ用の街区を事前生成する機能です。
巨大な元データ、未対応の形式、現実の通行判定の不足はこのコマンドだけでは解消しません。

## 実機での計測

街歩き画面の「動作の重さを計測」→「60秒の計測を開始」で、周囲を見ながら歩きます。
一時停止・非表示中は計測しません。完了後に「計測結果を保存」でJSONを端末へ保存できます。
平均FPSだけでなく、遅い側5%の境目となるフレーム時間と100ms超の停止回数を記録します。
取得できる場合のJSヒープ使用量はGPUやPC全体のメモリではありません。座標・URL・端末名・認証情報を含めず、外部へ送信しません。
計測機能を実装したことと、この開発環境で実機FPSを測れたことは別です。WebGL対応PCでの実測は引き続き必要です。
