# 大阪・梅田 街歩きプロトタイプ

製品としての第一段階は [日本地図で選んだ場所を、遊べる街にする](AREA_TO_PLAY.md) ことです。
この文書は現在の固定街区用の基盤を説明します。梅田は検証地点であり、全国エリア選択とAI自動構築は未実装です。

## 現在の到達点

これは実都市データを後から配置するための第一段階の実装です。梅田の再現完成版ではありません。
既存の対戦ゲームは `/` に残し、街歩きは `/walk.html` として分離しています。
予定範囲は1km×1km、既定の操作検証街区は250m×250mです。
一街区の形状・通行経路・表示品質が検証できるまで、全域が再現できたとは扱いません。

今回、実データ配布ページの取得はHTTP 403で未完了です。アクセス制限の回避は行っていません。
実都市データ・テクスチャ・実測の通行経路・現在の建物との一致は未検証です。
データ未取得時の画面は停止案内にし、明示的に選んだ架空の検証ステージのみ別モードで利用できます。

## 起動・操作

必要環境: Node.js 22 または24.13以上、npm、PCブラウザ、変換時のみPython 3.10以上。

```sh
npm ci
npm run dev:client
```

表示されたViteのURLの `/walk.html` を開いてください。実データがまだない場合、
「架空の検証ステージで操作を試す」から `/walk.html?fixture=1` を開けます。
街歩きには外部AI、WebSocket、クラウド設定、ログイン、APIキーは不要です。
実データ取得後の実行時も、同一オリジンの公開用データ以外へ送信しません。

| 操作 | 機能 |
| --- | --- |
| WASD | カメラ方向に合わせた移動。斜め移動の速度を正規化 |
| 左右Shift | ダッシュ（歩行3.2m/s、走行7m/s） |
| ドラッグ／矢印キー | 視点方向・高さの変更 |
| Esc／一時停止 | 移動を停止。タブ非表示・フォーカス喪失でも停止 |
| 開始地点へ | 安全確認済みの開始位置へ復帰 |
| 描画品質 | 軽量＝影なし・低解像度、標準＝影あり、高品質＝等倍解像度 |
| 検証ゲート | 架空ステージ限定の動的Collider。プレイヤーを挟む閉鎖を拒否 |

モバイルの移動操作・ゲームパッド・地下街・建物内部・マルチプレイ接続は今回の対象外です。

## データの取得と来歴

確認元（公開情報を2026-09-07に確認）:

- [PLATEAU公式オープンデータ案内](https://www.mlit.go.jp/plateau/open-data/)
- [大阪市2020年度データの配布ページ](https://www.geospatial.jp/ckan/dataset/plateau-27100-osaka-shi-2020)
- [e-Govの大阪市データ参照](https://data.e-gov.go.jp/data/dataset/mlit_20211007_0032/resource/5aed50c2-3bed-4e8d-a792-3de7da3e5649)
- [PLATEAUサイトポリシー](https://www.mlit.go.jp/plateau/site-policy/)
- [大阪市PLATEAU VIEWの案内](https://www.city.osaka.lg.jp/toshikeikaku/page/0000676393.html)
- [CityGMLの座標と標高の公式説明](https://www.mlit.go.jp/plateau/learning/tpc03-4/)

2020年度は確認できた候補であり、最新データの採用を確定したものではありません。
カタログの更新日、モデル整備年度、測量年度は別々です。再開発後の現在の梅田を保証しません。
最初の街区と1kmの原点は、建物・道路・地形と利用可能なLODを確認してから確定してください。
前提の欠けた地域を架空の地物で埋めないでください。

1. 配布元が案内する通常の方法で取得し、各リソースの個別利用条件・第三者権利・帰属表記を確認します。
2. 一街区に必要な建物、道路、地形のメッシュを選び、`data/raw/`（Git除外）に展開します。
   市全域をブラウザに読み込ませません。アーカイブの外部パス／シンボリックリンクを展開しないでください。
3. 下記のメタデータを `.local/source-metadata.json`（Git除外）に保存し、確認した値に置換します。
   測量年度が分からなければ `null` にします。条件未確認のまま実都市データを配布しません。
4. 入力ごとのSHA-256は変換プログラムが計算します。ローカル絶対パス、操作者名、鍵、署名付きURLは出力しません。

```json
{
  "title": "TODO: 取得したデータセット名",
  "provider": "TODO: 提供者",
  "datasetYear": 2020,
  "surveyYear": null,
  "url": "https://www.geospatial.jp/ckan/dataset/plateau-27100-osaka-shi-2020",
  "license": "TODO: 個別の利用条件",
  "licenseUrl": "https://www.mlit.go.jp/plateau/site-policy/",
  "attribution": "TODO: 提供元指定の帰属表記と加工した旨",
  "retrievedAt": "2026-09-07"
}
```

これは書式例です。年度・取得日・URLも実際に取得した資料に合わせます。TODOのままでは変換を拒否します。
複数入力は同一データセット／利用条件のものに限ります。異なる来歴の入力は別々に管理してください。

## 変換

付属の変換器はPython標準ライブラリのみを使用し、ネットワークアクセスしません。
次の座標は範囲選定用の例であり、安全な開始位置やデータの存在を確認済みという意味ではありません。
最初に出典の図郭と実際の道路を確認してください。`--spawn` は東・上・南方向のメートル座標です。
開始時は上から地面を検出し、建物の屋根が最初に当たる位置は拒否します。

```sh
python3 scripts/convert-citygml.py \
  data/raw/selected-building.gml data/raw/selected-road.gml data/raw/selected-terrain.gml \
  --source-metadata .local/source-metadata.json \
  --origin 34.705 135.4967 3 \
  --block-half-size 125 --spawn 0 2 50 \
  --out apps/game-client/public/city-data/umeda-block.json
```

入力ファイル名は説明用です。実際に取得したファイルを指定します。都市データはコミットしません。
再変換時の既存ファイルは上書きしないため、前回結果を退避してから実行してください。
ブラウザは固定の `/city-data/umeda-block.json` を読み、出典・配列・頂点数・開始位置などを検証します。
Webサーバーで配信したファイルは閲覧者が取得できます。非公開情報を公開ディレクトリへ置かないでください。

対応範囲と制約:

- UTF-8のCityGML 2.0、明示的なEPSG:6697、緯度・経度・標高の3要素のみ。軸順・座標系を推測しません。
- BuildingのLOD2 MultiSurface／Solid、LOD1 Solid、RoadのLOD1/2 MultiSurface、ReliefFeatureの三角形地形。
- 単純な閉じた平面ポリゴンのみ。凹形状はear clippingで三角形化します。
- 穴、未展開XLink、非平面、巨大なリング、未対応ジオメトリが選択入力内にある場合は拒否します。
  原データで全形式を検証済みではありません。必要ならレビュー済みの外部変換器で前処理する拡張が必要です。
- 建物と道路または地形が必要です。データのない場所へ平面を補完しません。
- 街区と交差する建物は全形状を保持し、境界に架空の壁面を生成しません。
- 1入力128MiB、出力20MiB、全体50万頂点、最大5,000メッシュで拒否する上限があります。
- 原点近傍をGRS80の局所接平面へ変換し、x=東、y=上、z=南、単位mにします。
  標高を近傍の相対高度として扱う近似です。ジオイド補正・測量精度の保証はありません。
- 元の写真テクスチャ／外壁属性は未取込。外壁・窓・点灯は汎用演出として常時明記します。

## 設計上の分離

| 層 | 内容 | 将来の変更 |
| --- | --- | --- |
| CityManifest | 原点、範囲、入力ハッシュ、年度、条件、形状 | データセット差替え、実測テクスチャ対応 |
| Visual World | 元の建物・道路・地形形状、夕景、外壁演出 | LOD／マテリアルを変更しても判定を変えない |
| Collision World | 非表示の独立メッシュ、地面、建物判定 | 別工程で簡略化・検証。現時点では元形状を複製 |
| Game Overlay | ゲーム範囲の壁、検証ゲート | 実測地物と区別した通行ゲート・障害物 |
| Existing PvP | 現行の架空都市とサーバー確定ルール | 実データ用の判定・経路グラフを接続後に統合 |

従来のworld-coreは格子道路と矩形Colliderを前提にします。新しい外観だけを重ねても、実際の道路と
サーバーの衝突が一致するわけではありません。PvP統合には同一の地図識別子・形状ハッシュ・サーバー判定・
Botの経路グラフ・動的ゲート検証を対応させる必要があります。

## 完了判定（残作業）

- 実データの年度・利用条件・LOD・範囲を確認し、初期街区を確定する。
- 原データで変換器を検証し、穴・XLink等に必要な前処理を決める。
- 建物外形・道路・地形・安全な開始位置を資料と照合する。
- PCブラウザで歩行・ダッシュ・壁沿い・カメラ・段差・落下復帰を確認する。
- 同じ視点で軽量／標準を計測。目標は標準30fps以上、軽量20fps以上（未達成・未測定）。
- データロード時間、最大メモリ、影の負荷を測り、形状の簡略化・分割読込を必要に応じて実装する。
- 初期街区を合格にしてから1km全域のタイル／LOD／経路対応へ広げる。

全域ストリーミング、GLB等の圧縮モデル、実測外観テクスチャ、NavMesh、実街区のPvP統合は未実装です。
公開用コードライセンスの新規付与は権利者の選択が必要なため、この変更では行いません。
