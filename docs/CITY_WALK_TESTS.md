# エリア選択・実都市街歩きの検証結果

実施日: 2026-09-07。Node.js 24.19.0 / npm 11.9.0 / Python 3.12.13。
固定依存の検証はmapbox-earcut 2.0.0、NumPy 2.2.6をvenvへ導入して実施した。
初期の変換計測には既設NumPy 2.3.5を使用し、同じ梅田街区を固定依存でも再構築した。

## 実データと性能

公式 [PLATEAU CityGML API](https://docs.plateauview.mlit.go.jp/datasets/citygml/) が解決した大阪市2025年度データを利用。
一般都市モデルのmetadata XMLでCC BY 4.0を確認し、追加制約フィールドがないことを確認した。
測量年度は不明。2025年度の形状を現在の街の完全再現とは扱わない。

| 計測 | 結果 |
| --- | --- |
| 梅田中心 34.705, 135.4967 | 建物・道路95メッシュ、15,501頂点、LOD上限2 |
| 元データ | 建物27,580,155 bytes＋道路1,422,915 bytes＝29,003,070 bytes |
| ブラウザ用JSON | 497,492 bytes、gzip 102,161 bytes（約99.8KiB） |
| 初回の確認・取得 | 初期確認31.78秒、元ファイルの取得と変換28.34秒。配布元通信を含む単発値 |
| 元ファイルがある場合 | Nodeサービス＋固定Python依存で1.657秒。別計測では4.432秒 |
| 確認キャッシュ | Nodeサービスの確認11.4ms |
| 完成ジョブ再利用 | 同一IDを返すまで0.17ms。HTTP／画面描画時間を含まない |
| 梅田西側 34.707, 135.491 | 同じ変換コードで134メッシュ、3,778頂点。元ファイル再利用の変換1.51秒 |

| 実機FPS／GPU／メモリ | 未測定。転送量・CPU衝突時間からFPSを推定しない |

上記2街区は250mの歩行範囲が重ならない別地点だが、同じ大阪市データセットである。
全国対応や他自治体での成功を示す検証ではない。
東京・丸の内は複数自治体のカタログ結果として拒否、福島駅付近は元データ容量上限で拒否した。
描画のために重い地域を無制限に取得することや、架空形状への代替は行っていない。

元ファイルのSHA-256:

- 建物: `1d4238ea5923cf0cc34dde79cfe4d64ec8d96e3d2593bec2fab28a5fb34f7175`
- 道路: `72e2257971a339f4f978c6305b2c5b4d9f073a9afe4ef52477ae3d745f1b4971`

正確な各配信URL、metadata ZIPのSHA-256、年度・条件・取得日は生成CityManifestに含める。
原データと生成形状はGitに同梱しない。

## 自動検証

- TypeScript: 16ファイル・101テスト。既存ゲームに加え、入力制限、AI計画の上限、同一オリジン判定、ジョブ再利用・取消・不正出力拒否、近傍Colliderを検証。
- Python: 14テスト。原点と軸、凹形状、穴の保持、非平面拒否、入力ハッシュ、XML entity拒否、取得先・リダイレクト制限、ライセンス未確認拒否、容量上限、道路上の開始地点を検証。
- 実データのNullEngine検証: 上記2街区で、上から最初に当たる面が道路であること、300フレームの接地で沈まないこと、4方向合計480フレームの移動で座標が有限かつ瞬間移動しないことを確認。
- CPU衝突計測: 中心街区は接地13ms＋方向移動15ms、西側は13ms＋19ms。GPU描画を行わない合計処理時間でありFPSではない。
- lint、typecheck、production build、地図バンドル容量ガード、公開前ガードを実施。最終CI結果はPR上のチェックを参照。
- lockfileはLeaflet 1.9.4と型定義の追加に限定。既存依存バージョンは変更していない。

## ブラウザで確認できたことと制約

地図タイルの表示、範囲枠・座標・候補地点・品質操作、実データ確認の成功表示、確認中・構築中・失敗案内を確認した。
実データ確認の成功は、通常の開発環境で取得・検証した15分以内の確認キャッシュを使用した。
新規構築はブラウザ検証環境がPythonの変換ライブラリを実行できず、DEPENDENCIES_MISSINGの案内で停止した。
通常のNode＋venv環境での実データ構築・gzip生成は上記の通り成功した。

構築済み実データを3D画面へ読み込ませたところ、ブラウザ検証環境ではWebGLを利用できなかった。
WEBGL_UNAVAILABLEを分類し、データを作り直す案内からブラウザ描画設定の案内へ修正した。
したがって、実3Dの目視・キー移動・描画の滑らかさ・追従カメラの視覚品質・実機FPSは未検証。
この制約を単体テスト成功やスクリーンショットで代替したとは扱わない。
既存Playwright E2E、長時間soak、モバイル実機、実AI、Docker／Cloud Runは未実施。

## 依存関係監査と公開前確認

`npm audit` は35件（critical 1 / high 9 / moderate 23 / low 2）を報告。既存ADK等の推移依存を含み、未解消。
CIのhigh以上のaudit gateは維持し、失敗を隠す設定にはしていない。強制一括更新や機能の削除は行っていない。
公開構築サーバーへの昇格には、この監査と認証・利用者別制限・実機検証を別途完了する必要がある。

秘密情報ガードは既知パターン・大容量ファイル・生都市データの混入を検知するヒューリスティック。
指摘0件は情報漏えいが存在しない証明ではない。秘密値・個人の会話・連絡先・生XML・キャッシュを公開変更へ含めない。
管理者権限が必要なGitHubのsecret scanning／push protection設定は変更していない。
