# エリア選択・実都市街歩きの検証結果

実施日: 2026-09-07。現行版はNode.js 24.19.0 / npm 11.9.0で検証した。
取得・変換・テスト・CIをTypeScriptへ統一し、Pythonの実行ファイル・依存定義・テストを削除した。
起動にはNode.js 22.19以上（22系）または24.13以上とnpmを使用する。

## 実データと移行の比較

公式 [PLATEAU CityGML API](https://docs.plateauview.mlit.go.jp/datasets/citygml/) が解決した大阪市2025年度データを利用。
一般都市モデルのmetadata XMLでCC BY 4.0を確認し、追加制約フィールドがないことを確認した。
TypeScript版でも公式APIの生応答と実metadata ZIPを検証した。測量年度は不明。
2025年度の形状を現在の街の完全再現とは扱わない。

## 変換の速度

同じ実データ・LOD2・元ファイルのキャッシュ2件を使い、旧版と現行版を交互に各3回実行した。
各回で新規子プロセスを起動し、取得ファイルの読込・変換・開始地点検証・JSON出力と親での受信解析までを計測した。
他のビルド・テストを同時に走らせない条件での値。ネットワーク取得、gzip生成、HTTP、GPU描画を含まない。
旧版の比較元は `79bdeb0`、Python 3.12.13 / mapbox-earcut 2.0.0 / NumPy 2.2.6。
現行版はTypeScript / Earcut 3.2.3 / saxes 6.0.0。

| 街区 | 旧Python版・中央値（範囲） | TypeScript版・中央値（範囲） |
| --- | --- | --- |
| 梅田中心 | 1.696秒（1.631〜1.724秒） | 2.392秒（2.385〜2.569秒） |
| 梅田西側 | 1.514秒（1.446〜1.533秒） | 2.447秒（2.430〜2.565秒） |

この環境では再構築が約0.7〜0.9秒増えた。移行を高速化の成果とは扱わない。
Pythonの準備を不要にし、TypeScriptだけで取得からゲームまで開発・起動できることが目的。
完成ジョブの再利用では変換を省略し、地図とゲームのブラウザ用コードへ変換ライブラリを追加していない。
初回のネットワーク取得は配布元に依存する。旧版で確認31.78秒、取得＋変換28.34秒を観測したが、現行版の初回時間を表す値ではない。

## 自動検証

- TypeScript: 18ファイル・137テスト成功。うち変換・取得の36テストを新設し、旧Pythonの14テストを移行・拡充した。
- 変換: 原点・軸、凹形状、穴、垂直面、非平面拒否、入力ハッシュ、重複除外、CRS・XLink・座標・閉鎖リング・出典の検証。
- 取得: 取得先・リダイレクト制限、Content-Lengthなしの容量超過、失敗レスポンスをキャッシュしないこと、ライセンス未確認／追加条件拒否、ZIPの重複・過大・不正パス、XMLのDTD・entity・NUL・非UTF-8拒否。
- 子プロセス: 本物のNodeワーカーによる検証エラーと即時中止を確認。既存ジョブの再利用・取消・不正出力拒否テストも成功。
- 実データのNullEngine: 両街区で上から最初に当たる面が道路であること、接地300フレームで沈まないこと、4方向合計480フレームの移動で座標が有限かつ瞬間移動しないことを確認。
- CPU衝突の合計時間: 中心は接地11ms＋方向移動16ms、西側は16ms＋15ms。GPU描画を行わない値でありFPSではない。
- `npm ci --ignore-scripts`、lint、typecheck、production build、地図容量ガードに成功。最終CI結果はPRのチェックを参照。
- lockfileは変換用依存7件の追加とNode.js最低版の更新に限定し、既存依存のバージョンを変更していない。

## プレビュー構築APIの確認

PATHを空にしてPythonや外部コマンドを検索できない環境で、Node.jsからVite previewを起動した。
HTTP経由の公式カタログ確認 → 構築ジョブ → 完成した95メッシュの受信 → 同じ完成ジョブの再利用が成功した。
元データ2件はキャッシュを再利用し、構築サービスの計測は2.609秒、HTTPとポーリング込みで2.707秒。
完成ジョブ再利用はHTTP込み4.75ms、配信ヘッダーはgzip、圧縮後104,728 bytesだった。
実際のNode子プロセスを使ったAPI検証であり、ブラウザ描画の計測ではない。

## ブラウザと実機の制約

移行前に地図タイル、範囲枠、座標、候補地点、品質操作、確認成功・処理中・失敗の表示を確認した。
当時のブラウザ検証環境にはPythonライブラリの制約があった。現行版はその依存を削除したが、ブラウザ操作の通し検証を再実施したとは扱わない。

同ブラウザはWebGLを利用できず、実3Dの目視・キー移動・滑らかさ・追従カメラの視覚品質・実機FPSは未検証。
単体テストやNullEngineの成功を、見た目やFPSの受入完了とは扱わない。
Windows実機、既存Playwright E2E、長時間soak、モバイル、実AI、Docker／Cloud Runは未検証。
